01

Hermes — 有長期記憶的 AI 生活夥伴

問題：市面上的 AI 助理沒有跨對話的長期記憶，也不能自己長出新能力。

自建 Telegram gateway，後端接大型語言模型 API，可多 profile 併行（生活／科技評估各一套人格與工具）。 記憶層落在 Obsidian 知識庫：對話摘要、帳務、財務快照全部結構化寫檔， 重開機、換模型都不失憶。skill 系統讓它能載入新工具（查核、產圖、行程）， 並設計了受控的自我更新閉環——它可以在人審核的前提下改自己的設定。

  • Telegram Bot API · LLM provider 抽象層 · AI 協作開發
  • Obsidian 檔案型記憶金庫 · skill 插件系統
  • systemd 常駐 · 每日實際使用中

● stock-monitor.timer — active (waiting) · 每交易日 13:35

02

Stock Monitor — 台股 AI 決策研究平台

問題：LLM 到底能不能做交易決策？口說無憑，讓多個 AI 帳戶每天真的下判斷、然後被記分。

每個交易日排程自動抓行情與財報基本面，餵給多個獨立 AI 交易帳戶 （含 K 線專用模型與通用 LLM）各自做出買賣決策，寫入資料庫並推播摘要。 決策會進入評估迴圈：定期回測、淨值互相 PK、表現差的策略被機制性淘汰 ——包含一次用回測數據否決掉一個看起來很聰明的策略。

  • 行情 API · cron 排程 · Streamlit 儀表板 · AI 協作開發
  • 多帳戶 AI trader · 回測驗證 · 每日決策通知
  • 研究用途 · 決策全程留痕可稽核

● mobile-status-page.service — active (running) · :8504

03

ESP32 Usage Monitor — 從韌體到儀表板

問題：AI 服務的用量與額度散在各處，想在桌上一顆小硬體和手機上隨時看到。

ESP32 硬體端顯示即時用量，主機端跑狀態伺服器供手機瀏覽， 資料鏈從 API 抓取、彙整到雙端呈現一手包辦。 規模不大，但完整走過「韌體 → 後端 → 前端」的垂直整合。

  • ESP32 · 狀態伺服器 · 行動版頁面 · AI 協作開發

● fusion-panel.service — active (running) · :8503

04

Fusion Panel — 多模型辯論協調器

問題：單一模型的答案有盲點，重要決策想聽多個模型互相挑戰後的結論。

用 CLI 召集多家模型（Google、OpenAI 系、開源模型）對同一命題輪流立論與反駁， 最後由協調者整合成單一結論。重點在 provider 抽象與回合制編排—— 任何一家模型換掉，辯論照常進行。

  • 多 LLM provider · 回合制編排 · Web 面板 · AI 協作開發
